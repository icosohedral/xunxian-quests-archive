# 寻仙任务信息 Web 原型 · AI Vibecoding 执行计划

## 1. 产品目标

为本地 SQLite 任务数据库建立一个无需外部服务、启动简单、只读安全的 Web 原型。

这个原型的首要任务只有一个：

> 让使用者通过任务名称、NPC、地区和分类找到任务，并在一个页面内看懂任务文本、目标、奖励、关系和来源。

目标用户是任务数据整理者、剧情/文案查看者和后续工具开发者。本阶段不做游戏编辑器、不修改数据库、不实现账号系统，也不推断数据库中尚未确认的游戏逻辑。

## 2. 推荐技术方案

| 层级 | 方案 | 选择理由 |
|---|---|---|
| 数据库 | SQLite，只读 URI 连接 | 直接使用现有 `quest.db`，禁止页面误写数据 |
| 后端 | Python 3.11+、FastAPI、原生 `sqlite3` | 与现有项目一致，API 明确，AI 容易测试和维护 |
| 页面 | Jinja2 服务端渲染 | 首屏快，不需要复杂前端构建链 |
| 局部交互 | HTMX 或少量原生 JavaScript | 搜索、筛选、抽屉和分页无需完整 SPA |
| 样式 | 原生 CSS 变量与组件类 | 保持设计可控，避免模板化组件库外观 |
| 关系展示 | 原生 SVG | 本地可用、无 CDN 依赖，可处理一至两层任务关系 |
| 测试 | pytest + FastAPI TestClient + Playwright | 同时覆盖数据、接口、桌面端和移动端 |

### 启动目标

```bash
cd apps/quest_viewer
uv run uvicorn quest_viewer.app:app --reload
```

浏览器打开 `http://127.0.0.1:8000`。

数据库路径由环境变量 `QUEST_DB_PATH` 指定；未指定时使用发布版数据库：

```text
outputs/quest_database/releases/1.0.0/quest.db
```

## 3. 输入与安全边界

### 允许读取

- `outputs/quest_database/releases/1.0.0/quest.db`
- `outputs/quest_database/releases/1.0.0/docs/query_examples.sql`
- `outputs/quest_database/releases/1.0.0/docs/database_schema.md`
- `src/questdb/views.sql`

### 禁止操作

- 不得修改、复制覆盖或迁移 `original_data/**`。
- 不得对正式 `quest.db` 执行 `INSERT`、`UPDATE`、`DELETE`、`DROP` 或建表操作。
- 不得把未知字段、标志位、脚本列或条件代码解释成确定语义。
- 不得把不同编号空间混用，例如 `target_id=91` 不等于 `quest_npc_id=91`。
- 不得通过 CDN 加载运行必需的脚本、字体或图标；原型离线时仍应可用。
- 不得为了页面好看而省略 unresolved、source_file、source_row 等审计信息。

### 数据连接要求

使用 SQLite 只读 URI：

```python
sqlite3.connect(f"file:{db_path}?mode=ro", uri=True)
```

所有查询必须参数化。应用启动时检查：

- 数据库文件存在；
- `PRAGMA integrity_check` 返回 `ok`；
- `quest_full` 等 6 个视图存在；
- 不创建或修改任何数据库对象。

## 4. 信息架构

### 页面 A：任务检索

- 支持任务名称模糊查询。
- 支持 NPC、地区、分类筛选。
- 前台不显示任务 ID；数据库关联和页面跳转仍可在内部使用 ID。
- 分类按所属任务数量降序排列，并显示任务数量。
- 地区按该地区最低任务等级升序排列。
- 结果展示名称、等级、接取/提交 NPC、地区和文本状态。
- 支持分页、空结果、加载中和查询错误状态。
- 最近打开的任务仅保存在浏览器本地，不写入数据库。

### 页面 B：任务详情

按以下顺序展示：

1. 任务标题、ID、版本、等级和分类；
2. 接取 NPC、提交 NPC、地区和追踪目标；
3. 接取对话、背景描述、提示、进行中对话、完成对话；
4. 前置条件和任务目标；
5. 奖励；
6. 前后续任务与其他任务引用；
7. 原始来源、解析状态和未确认字段提示。

任务 11257 在 Web 展示层合并为一个任务：

- 主名称使用原始文件中较早出现的 `孟浪多疑10`；
- `孟浪多疑11` 作为别名展示；
- 页面明确标记“检测到同 ID 原始记录”；
- 同时保留并展示原始第 6211、6212 行；
- 不删除或覆盖数据库中的两个物理版本。

### 页面 C：关系聚焦视图

- 显示当前任务、直接前序和直接后续。
- 区分 `next` 与 `task_object_reference`。
- 环路只提示，不无限展开。
- 点击关系节点可进入对应任务。

### 文本标签交互

解析但不破坏原始文本：

- `<target:91>`：按 `quest_target.target_id` 解析。
- `<enemy:黄风打手>`：结合当前任务目标和 NPC 名称解析。
- 不能唯一解析时显示“未确认”，不得按名称强行绑定。
- 鼠标悬停或点击标签，显示编号空间、实体名称、地区、资源键及解析证据。
- 页面应同时允许查看未经转换的原始标签。

## 5. 视觉方向

### 设计概念

采用“任务卷宗台”而不是通用后台仪表盘：界面像在翻阅一套经过整理的仙侠任务档案，但保持现代、高密度和易读。

### 设计令牌

| 名称 | 色值 | 用途 |
|---|---|---|
| 宣纸灰 | `#F2F3ED` | 主背景 |
| 墨蓝 | `#17313A` | 标题、导航和主文字 |
| 松青 | `#2F6B61` | 已解析、可点击关系 |
| 朱砂 | `#C64B3C` | 当前任务、重点操作 |
| 铜金 | `#B38A48` | 等级、版本和来源标记 |
| 雾灰 | `#D8DDD8` | 分隔线、禁用和空状态 |

- 展示字体：优先使用本地 `LXGW WenKai`，没有时回退到 `STKaiti`、系统中文字体。
- 正文字体：`PingFang SC`、`Noto Sans SC`、系统无衬线字体。
- 数据和 ID：系统等宽字体。
- 不使用紫蓝渐变、玻璃卡片、悬浮装饰球或无意义的大数字卡片。

### 布局

桌面端使用三段式工作台：

```text
┌──────────────┬────────────────────────────┬──────────────────┐
│ 搜索与结果   │ 当前任务卷宗               │ 关系与来源       │
│ 320px        │ 自适应                     │ 300px            │
│              │ 标题 / 文本 / 目标 / 奖励  │ 任务链 / 解析证据│
└──────────────┴────────────────────────────┴──────────────────┘
```

移动端改为单列，搜索抽屉和关系抽屉从底部打开。

### 标志性交互

页面最值得记住的元素是“可解析的任务文本”：`<enemy:...>`、`<target:...>` 在正文中显示为带编号空间标记的交互标签，点击后直接看到它如何连接到 NPC、目标、地区和任务配置。

只使用一处明确动效：打开任务时，标题、核心属性和正文依次轻微显现；必须支持 `prefers-reduced-motion`。

## 6. AI 执行协议

1. 执行前通读本计划、数据库说明和查询示例。
2. 按任务编号和依赖顺序执行，同一时间只处理一个任务。
3. 每项任务开始时把状态由 `pending` 改为 `in_progress`。
4. 只有必须产出与自动验收全部通过，才能改为 `completed`。
5. 保存测试命令、退出码、截图和修改文件清单。
6. 遇到审批门必须停止，等待用户明确批准。
7. 页面必须使用真实任务数据，不使用 Lorem Ipsum 或虚构任务。
8. 每完成一个页面，至少检查任务 2、任务 90、任务 11257。
9. 桌面端和移动端都必须进行浏览器截图检查。
10. 发现数据库问题时记录问题，不在 Web 项目中静默修复数据库。

## 8. 各任务执行要求

### WEB01 · 项目骨架

必须产出：

- 独立 Python 包和依赖声明；
- `QUEST_DB_PATH` 配置；
- `/health` 健康检查；
- SQLite 只读连接工厂；
- 本地静态资源目录；
- 基础测试入口。

不得复制数据库到源码目录，不得修改项目现有数据库构建代码。

### WEB02 · 数据查询层

定义稳定的数据对象：

- `QuestSummary`
- `QuestDetail`
- `QuestText`
- `QuestEndpoint`
- `QuestObjective`
- `QuestReward`
- `QuestRelation`
- `QuestLocation`
- `ResolutionEvidence`
- `QuestAlias`
- `QuestSourceVariant`

列表查询必须有分页上限。详情查询应批量获取关联数据，避免模板内循环访问数据库。

对于同一 `quest_id` 的重复记录，Repository 应执行无损合并：

- 按 `source_row` 最小值选择展示主记录；
- 收集所有不同名称为别名；
- 仅当其余字段完全一致时标记 `safe_display_merge=true`；
- 任意其他字段不一致时不得自动折叠，必须返回冲突字段列表；
- 合并只发生在返回模型中，不写回 SQLite。

### WEB03 · 路由与 API

建议接口：

```text
GET /health
GET /
GET /quests/{quest_id}?version=1
GET /api/quests?q=&npc=&area=&category=&page=
GET /api/quests/{quest_id}?version=1
GET /api/quests/{quest_id}/relations?depth=1
```

API 中必须保留 `resolved`、`source_file`、`source_row` 和 `version_no`。

### WEB04 · 视觉预览

使用真实数据制作：

- 任务 2：完整新手任务；
- 任务 90：文本标签解析场景；
- 任务 11257：重复 ID 无损合并、别名和双来源场景。

G-WEB-01 前不扩展完整功能，先让用户确认布局、密度、颜色和文本阅读体验。

### WEB05–WEB09 · 核心功能

- 搜索条件应写入 URL，刷新页面后仍可恢复。
- 任务文本保留换行和原始标签。
- 空文本明确显示“原始数据为空”，不隐藏字段。
- 奖励区分组、槽位、数量和解析状态。
- 关系图同时提供无障碍文本列表。
- 未确认的比较代码只显示原值和“语义未确认”。

### WEB10–WEB11 · 体验与质量

至少覆盖：

- 1440×900 桌面端；
- 390×844 移动端；
- 键盘 Tab 顺序；
- 加载、无结果、任务不存在、数据库不可用；
- 超长文本；
- 无文本任务；
- 关系环路；
- 11257 合并展示、别名和两个原始来源；
- HTML 标签转义和 SQL 注入输入。

建议性能目标：

- 本地首屏小于 1 秒；
- 普通搜索和详情查询小于 300 毫秒；
- 单次列表最多返回 50 条；
- 关系图默认只展开 1 层。

### WEB12 · 本地交付
